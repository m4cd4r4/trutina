## Why this doc exists

The Claude Design system iterated three rounds against a synthetic schema that does not match the live frontend's `Case` / `FraudFlag` / `Broker` types. Porting JSX pattern-for-pattern would render half-empty against real data and would assert marketing figures that have no provenance. This file is the source of truth for how the visual port reconciles the two, so the same decisions are not re-litigated in every component.

Three families of mismatch are addressed below.

1. Flag taxonomy: 6 backend categories vs 5 design-system modules.
2. Evidence shape: untyped `Record<string, unknown>` vs a rich crop / SHA / rule / ledger schema.
3. Marketing figures: stated as measured numbers with citations that do not exist in our data.

## 1. Flag categories -> design-system modules

Backend `FlagCategory` (lib/types.ts line 3):

```
pdf_forensics | ai_content | cross_reference | consistency | broker_risk | identity
```

Design-system modules (ui_kits/app/data.js):

```
Producer metadata | Identity coherence | Income arithmetic | Employer verification | Network clustering
```

Proposed map (1:1 except `pdf_forensics + ai_content` collapse together because both speak to "what tool made this file"):

| Backend category   | Design-system module    | Rationale                                                                 |
|--------------------|-------------------------|---------------------------------------------------------------------------|
| `pdf_forensics`    | Producer metadata       | PDF producer string, font fingerprint, object stream - same surface.      |
| `ai_content`       | Producer metadata       | "Was this generated by a tool, and which one" - same question as PDF.    |
| `identity`         | Identity coherence      | Direct match.                                                             |
| `consistency`      | Income arithmetic       | Math/date consistency in payslip is the income-arithmetic surface.       |
| `cross_reference`  | Employer verification   | ABN lookup / ASIC register / BSB directory all employer-verification.    |
| `broker_risk`      | Network clustering      | Submission velocity, shared-employer clustering, broker-network signal.  |

The collapse from 6->5 means **Producer metadata module** receives flags from two backend categories. The module-card UI keeps a single header; flags inside it preserve their original category in a sub-label (small caps under the title).

### Module-score derivation

The design system shows a per-module score 0-100 and a per-module severity tier. The backend returns one overall `case.risk_score` and per-flag `severity` + `weight`. No per-module aggregate exists today.

Proposed derivation (deterministic, no backend changes):

```
module.flags        = flags whose category maps to this module
module.severity     = max(flag.severity) across those flags   (crit > high > med > low)
module.score        = sum(flag.weight) clamped to 0..100      (matches backend's existing weight scale, already in flag.weight)
module.flagCount    = module.flags.length
```

If a module has zero flags, it renders with `severity: low` and `score: 0` and the muted "no flags" state. The brief's "module-card filters the flag list" interaction works against this derivation without any new backend field.

Open question for review: is `sum(weights)` the right module score, or should it be `max(weight)`? The design kit treats module score as a magnitude reading; sum communicates "how many bad things in this module" better than max. Default: **sum, clamped at 100**.

## 2. Evidence stub: required fields vs available data

The evidence stub (case-detail.jsx -> `EvidenceStub`) expects:

```
filename, sha256, page, pageCount, crop {x,y,w,h}, byteOffset,
ruleId, ruleDesc, firedAt, firedMs
```

Backend `FraudFlag` provides:

```
id, category, code, title, description, severity, weight,
evidence: Record<string, unknown>, document_id
```

Mapping:

| Stub field       | Source                                                         | Fallback when missing                                                |
|------------------|----------------------------------------------------------------|----------------------------------------------------------------------|
| `ruleId`         | `flag.code`                                                    | Hide rule-id badge entirely.                                         |
| `ruleDesc`       | `flag.description`                                             | Hide sub-line.                                                       |
| `filename`       | document lookup by `flag.document_id` -> `DocumentSummary.filename` | Render "Source document not linked" as monospace caption.       |
| `page`           | `flag.evidence.page` if present (typed assertion)             | Hide page indicator.                                                 |
| `pageCount`      | `DocumentSummary.page_count`                                   | Hide page indicator.                                                 |
| `sha256`         | `flag.evidence.sha256` if present                              | Hide ledger row.                                                     |
| `crop`           | `flag.evidence.crop` if present (validated shape)              | Hide crop preview; widen ledger to full width.                       |
| `byteOffset`     | `flag.evidence.byte_offset` if present                          | Hide ledger row.                                                     |
| `firedAt`        | `flag.evidence.fired_at` if present                            | Fall back to case.analysed_at; if also null, hide row.               |
| `firedMs`        | `flag.evidence.fired_ms` if present                            | Hide.                                                                |

Rule: the evidence stub **always renders the head (rule code + title) and the foot (immutable ledger statement)**. The body sections (crop, ledger rows) collapse cleanly when absent. No fabricated SHAs, no placeholder crop coordinates. The "Copy citation block" button only copies fields that actually exist.

This is implemented as a typed adapter in `lib/case-modules.ts`:

```ts
type EvidenceView = {
  ruleId: string | null
  ruleDesc: string | null
  filename: string | null
  page: number | null
  pageCount: number | null
  sha256: string | null
  crop: { x: number; y: number; w: number; h: number } | null
  byteOffset: string | null
  firedAt: string | null
  firedMs: number | null
}

export function evidenceView(flag: FraudFlag, doc: DocumentSummary | null): EvidenceView
```

`DEMO_CASES` in [lib/demo-data.ts](file:///i:/Scratch/trutina-design-system-migration/frontend/lib/demo-data.ts) is extended to include the richer evidence fields on the AI-fake and forged-statement specimens, so the demo surface visually exercises the full stub. The five existing demo cases keep their identity; new fields are added.

## 3. Marketing figures

The marketing hero in `ui_kits/marketing/sections-top.jsx` states four numbers with citation-style sources:

| Claim                                                                  | Source string in kit                              | Real provenance? |
|------------------------------------------------------------------------|---------------------------------------------------|------------------|
| 2.7% measured fraud rate (24w, all customers)                          | CONFIRMED-FRAUD / SUBMISSIONS . 2025-11 to 2026-04 | None.            |
| 0.41% false-positive rate on Cleared cases                             | REVIEWER-OVERTURNED / FLAGGED . measured           | None.            |
| 11s median time to verdict                                             | P50, file ingest to module output                  | None.            |
| 17min median reviewer time saved per case                              | CUSTOMER-REPORTED . n=6 lenders [2]                | None.            |

The kit also references a fabricated AFR headline:

> 2026-04-08 AFR: Westmead Building Society freezes 41 broker channels after producer-metadata audit.

The Trutina design system README itself says, under "Content fundamentals":

> Uncited statistics on the marketing site. If we cannot footnote it, we cut it.

So:

- **Replace the AFR Westmead headline** with the real CBA self-reported ~A$1B fraud headline that the current landing already cites (Feb 2026). Keep the disclosure-block visual treatment.
- **Cut the four trust-strip numbers** for this PR. The strip stays in the layout but renders a single-line note: "Calibration metrics published in the methods paper. Updated quarterly." Linked to a /methods page (placeholder route, out of scope for this PR; record in CLAUDE-TODO).
- **Footnote [3] (APRA CPG 234)** and **[6] (ATO SG rate schedule)** remain - both are real public references.
- **Footnote [1] (AFR Westmead)** is replaced with the real CBA Feb 2026 reference already in use.
- **Footnote [2] (n=6 lenders methodology)** is dropped along with the time-saved claim.

This is a small but load-bearing edit. The brief said "British English, no em-dashes" but is silent on uncited claims; the design system's own README is loud on uncited claims, and the README wins.

## 4. Broker view: 24-week cadence + cluster panel

Backend `Broker` provides:

```
broker_name, broker_abn, broker_license, submission_count,
fraud_flag_count, risk_score, first_seen_at, last_seen_at
```

Design system expects:

```
aggregator, fraudRate (decimal), tierBreakdown(weeks=24): {l,m,h,c}[],
clusterCases [], sharedProducerSignature, region
```

Mapping:

| Design field             | Source                                                      | Fallback                                                                |
|--------------------------|-------------------------------------------------------------|-------------------------------------------------------------------------|
| `aggregator`             | not available                                               | Hide the "via {aggregator}" sub-line.                                  |
| `fraudRate`              | `fraud_flag_count / submission_count`                       | Show "n/a" if `submission_count = 0`.                                  |
| `tierBreakdown`          | computed from `cases` list filtered by `broker.id`          | If fewer than 4 weeks of data, render an empty-state panel: "Cadence chart available after 4 weeks of submissions. Currently {n} submission(s)." |
| `clusterCases`           | not available today                                         | Render an empty-state panel: "No shared-producer signature detected across this broker's last 60 days." |
| `sharedProducerSignature`| not available today                                         | Implied by above empty state.                                          |
| Region (NSW + VIC etc.)  | not available                                               | Hide.                                                                  |

Cluster detection requires a backend addition (group cases by producer-string hash across a broker's submissions in N days). Captured in CLAUDE-TODO as a follow-up; this PR ships the empty-state panel.

## 6. Tier vocabulary

Design system uses `crit / high / med / low`. Backend uses `critical / high / medium / low`. Mapping function:

```ts
export const tierToken = (lvl: RiskLevel | null) =>
  lvl === 'critical' ? 'crit' :
  lvl === 'medium'   ? 'med'  :
  lvl ?? 'low';
```

CSS classes use the design-system spelling (`risk-crit`, `risk-med`) since they come from `colors_and_type.css` verbatim.
